1The Problem

During peak hours (lunch / dinner), the entire application becomes unresponsive for 1–4 minutes. All ~150 live restaurants (5–10 concurrent devices each) see:

SymptomWhere the user sees it
HTTP 500 errorsOrder placement, reports, any API action
API timeoutsOrder placement hangs, spinners never resolve
Delayed / missing socket updatesKitchen displays wrong, table statuses stale
Temporary app hangsCashiers panic-refresh → which adds even more load

2Root Cause — How the Outage Happens

Verdict — PROVEN LIVE 2026-07-19 Primary culprit: backend/infra — now confirmed with a live authenticated test. A logged-in client of restaurant 644 received unsolicited socket events for restaurants 689 and 523 within 4 minutes (own=0, foreign=6). The socket server broadcasts every event globally to all restaurants on the default namespace (no rooms). The API origin also collapses under load (Cloudflare 521 = origin down, observed twice). The frontend is a contributing amplifier, not the source: its handlers turn each broadcast into simultaneous API calls, retries have no jitter, and a reconnect race can double connections.

The amplification chain (traced in code)

1 waiter places an order └─ Laravel emits 3–5 socket events (new-order, food-status, order-status, engage, table) └─ ❌ NO ROOMS → each event is written to ALL ~600–1,500 connected sockets (all 150 restaurants receive all events; clients filter by event name) └─ ❌ 3 event types carry NO payload → every device of that restaurant (5–10 clients) simultaneously calls GET /single-order └─ API slows under herd → fetch fails → fixed 1s retry (no jitter) └─ MORE simultaneous load → 500s / timeouts └─ sockets drop → EVERY client refetches ALL running orders on reconnect (rehydration herd) └─ origin saturates → Cloudflare 521 (origin DOWN) └─ 1–4 min death spiral until the herd subsides

Phase B — Fixes (in priority order)

BE-B1 · Implement room protocol P0SOCKET SERVER
On connection: require join with restaurantId + token validation → socket.join('rest_'+rid). Change every io.emit(channel, ...) → io.to('rest_'+rid).emit(channel, ...). Keep old global emit temporarily behind a flag for backward compatibility during rollout.
How we check: run the wire probe (§6.1) from restaurant A — zero foreign-restaurant events received. Expected wire-traffic drop ≈ 99.3% (1/150).
BE-B2 · Payload-complete status events P0API + SOCKET
Include the full order object in update-order-status / update-food-status emits so clients stop calling GET-back. The FE already supports payload events (EVENTS_WITH_PAYLOAD) — no FE change needed to benefit.
How we check: place 1 order, change its status; API access log shows ZERO GET /single-order bursts from that restaurant's devices.
BE-B3 · Serve production frontend as static build P0-VERIFYINFRA
Verify what serves the production bundle. If it is craco start (dev server — ARCH bible FDEP-04), it caps at ~100 connections and is an outage-class bug on its own. Replace with yarn build + nginx/CDN.
How we check: response headers of the prod app URL show nginx/CDN, not webpack-dev-server; no /sockjs-node or HMR endpoints exposed.
BE-B4 · Kill duplicate scan-new-order payloads P1SOCKET SERVER
Stop emitting v1+v2 formats simultaneously; version the protocol and deprecate v1.
How we check: wire probe shows exactly 1 event per scan order.
BE-B5 · Redis adapter — only when adding a 2nd socket node P2INFRA
Not needed on a single node. Mandatory the moment horizontal scaling starts, together with sticky sessions on the LB (polling fallback transport breaks without them). Rooms (BE-B1) are the prerequisite.
How we check: N/A until multi-node; then: events emitted on node 1 reach clients on node 2.

5Frontend Workbook — What Frontend Has To Do

All items go through the normal gate flow (Intake → Planning → Gate 4 GO → Implementation → QA). Socket files are hotspots — no Fast Lane. Verification after implementation is done by the testing agent, not by inspection.

FE-1 · Fix connect() duplicate-socket leak HIGHsocketService.js
In connect() (socketService.js:43-71): before creating a new io() socket, fully tear down any existing one (disconnect() + remove listeners + clear eventHandlers map entries). Guard must handle the "exists but reconnecting" state, not just "connected".
How we check: QA: kill network 5s → restore → toggle tab visibility repeatedly; getDebugInfo() + server clientsCount show exactly 1 connection per device; no double event logs.
FE-2 · Jitter + backoff on all herd paths HIGHsocketHandlers.js · useSocketEvents.js · useOrderPollingReconciliation.js
(a) fetchOrderWithRetry: replace fixed 1s retry with exponential backoff + random jitter. (b) Reconnect rehydration: add 0–5s random delay so 1,000 clients don't refetch in the same second. (c) 60s poll: add per-client random phase offset.
How we check: simulate a 3s disconnect for multiple clients; API access log shows rehydration requests spread over ≥5s window, not a single spike.
FE-3 · De-duplicate in-flight single-order fetches MEDIUMsocketHandlers.js
Multiple events for the same orderId within a short window currently trigger multiple concurrent GETs. Keep a per-orderId in-flight promise map; reuse it.
How we check: emit 3 status events for the same order within 1s (test harness); Network tab shows exactly 1 GET.
FE-4 · Send restaurantId + token in handshake auth MEDIUMsocketService.js · socketEvents.js
Add auth: { restaurantId, token } to connection options and emit join after connect. Harmless with today's server; enables BE-B1 room rollout to be backward-compatible. Also closes the "any client can receive all events" security gap once server validates.
How we check: handshake request (DevTools → WS frames) contains auth payload; after BE-B1, server rejects join with a bad token.
Testing rule Every FE item above is verified by the testing agent after implementation (mandated) — plus the wire probe and the peak-window numbers from §6. Self-inspection alone does not close an item.

6How We Check — Verification Playbook

6.1 The 5-minute wire probe (decisive: global vs room broadcast)

Run in DevTools console of any logged-in POS tab during business hours. Full script: /app/memory/evidence/INV-SOCKET-001/wire_probe.js

// counts every event arriving on the wire, split own vs foreign restaurant
const sock = window.__SOCKET_SERVICE__.getSocket();
const myRid = String(JSON.parse(localStorage.getItem('restaurant')||'{}').id);
const stats = {own:0, foreign:0, bytes:0};
sock.onAny((ev, ...a) => {
  stats.bytes += JSON.stringify(a).length;
  (ev.endsWith('_'+myRid) ? stats.own++ : stats.foreign++);
});
// ...wait 5 minutes, then:
console.log(stats);
// foreign > 0  ⇒  GLOBAL BROADCAST CONFIRMED (with real events/sec + KB/sec numbers)

9Key Learnings (updated after live test)

The clincher: a non-order event proved it The 6 foreign events were on channel login_disabled_<rid> — a system/admin event, not order traffic. That is why restaurants 689 & 523 fired them despite having no orders running. The order channels showed own=0 simply because test restaurant 644 was quiet. The frontend has zero references to login_disabled — it never subscribes to it, yet still received it. Receiving an unsubscribed foreign channel is the cleanest possible proof of raw io.emit() fan-out to the default namespace.
#Learning
1Global broadcast PROVEN (not inferred): client 644 got foreign events for 689 & 523 in 4 min.
2Proof came from login_disabled_<rid> (admin/system event) — orders were NOT needed to prove it.
3Client isolation is name-filtering only → any stray wildcard listener = cross-tenant data leak (privacy + perf).
4Earlier "443 refused / Apache" was an outage artifact. Healthy socket host = nginx 1.18.0 + Socket.IO v4, websocket upgrade OK.
5Origin flaps: Cloudflare 521 at 03:19 AND 04:12 UTC, recovered by 04:19 — intermittent origin death is a distinct confirmed symptom.
6Handshake accepts unauthenticated sockets (no token) → anyone can open a socket and, given global broadcast, receive the whole fleet's events.
