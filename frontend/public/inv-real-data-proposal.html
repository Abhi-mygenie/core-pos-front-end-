{
"quantity": 0, // no stock being added — physical recount only
"unit": "pkt", // ← item.displayUnit e.g. "pkt" / "tin" / "bottle"
"physicalqty_master": true, // flags this as a physical count operation
"physical_qty": 4600, // ← raw user-entered value (in gm, base units)
"waste_reason": "Physical stock count",
"wastage_reason_id": null,
"notes": ""
}
⚠️ The unit mismatch question
"unit": "pkt" is sent alongside "physical_qty": 4600 (which is in grams).

If backend reads unit to interpret physical_qty, it would think 4600 packets — completely wrong.

Before approving any fix, we need to confirm:
Does the backend use the unit field to interpret physical_qty?
Or does it ignore unit for physicalQty and always treat it as the ingredient's base unit?
✅ What the drift fix (Option A) changes in the payload
Nothing in the API payload. The drift fix only changes the display label in the UI badge.

"physical_qty": 4600 still goes to the backend unchanged.

The FE never sends a "drift" field. The backend calculates drift internally by comparing physical_qty against its own stored quantity record.

If backend ignores unit for physicalQty → only 1 file change (display fix).
If backend uses unit to interpret physicalQty → also need to change unit: item.smallUnit in save path.
