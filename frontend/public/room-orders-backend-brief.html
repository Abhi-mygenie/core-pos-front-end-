Backend Engineering Brief

Room Orders Aggregation Endpoint

Dedicated server-side aggregated endpoint for the Room Orders Report. Replaces front-end filtering of the generic order-logs-report.

Date 2026-08-26 Priority P1 Feature Room Report — Aggregation Migration Requested by Frontend Team
Problem Statement
Current approach is inefficient: The Room Orders Report fetches the generic order-logs-report (returns ALL orders for a date range) and performs all filtering, grouping, and financial computation in the browser (JavaScript). This creates large payloads, slow load times, and no server-side pagination.
Current (Front-end Filtering)
Downloads ALL orders for date range (~500KB–2MB)
FE filters order_in = 'RM' from full list
FE groups SRM associated orders by parent_order_id
FE computes food totals, folio, outstanding per row
FE computes KPI aggregates (sum, count)
No server-side pagination
Slow on large date ranges / busy restaurants
New (Backend Aggregation)
Returns rooms only (~20–50KB)
SQL WHERE order_in = 'RM'
SQL JOIN on parent_order_id
Pre-computed financials — FE just renders
Pre-computed summary block in response
LIMIT / OFFSET pagination
Fast even for 90-day ranges

Server-Side Filtering Logic
SQL (pseudo-code)SQL
-- Base filter (always applied)
WHERE orders.order_in = 'RM'
  AND orders.restaurant_id = :restaurant_id
  AND orders.order_status NOT IN ('cancelled', 'merged')
  AND orders.created_at BETWEEN :from_date ' 00:00:00' AND :to_date ' 23:59:59'

-- Status filter
IF status = 'paid':     AND orders.f_order_status = 6
IF status = 'unpaid':   AND orders.f_order_status != 6
IF status = 'in_house': AND orders.f_order_status != 6
                          AND NOW() BETWEEN room_info.checkin_date AND room_info.checkout_date

Implementation Notes
NoteDetail
room_payment_summaryReuse the exact same structure already shipping in the running orders API. No need to redesign — just include it per room row.
SRM ordersAssociated sub-orders have order_in = 'SRM' and parent_order_id = RM.order_id. JOIN and SUM their order_amount into food_total.
room_noShould be the human-readable label (e.g. "101") from the rooms table, not the internal room_id.
Cancelled/mergedExclude order_status IN ('cancelled', 'merged') — these are current "anomalies" the FE drops silently.
nightsCEIL(TIMESTAMPDIFF(SECOND, checkin_date, checkout_date) / 86400) — minimum 1.
Summary is always over full result setSummary totals should reflect ALL rooms matching the filter (not just the current page).
AuthBearer token. restaurant_id derived from token — not sent in payload.
