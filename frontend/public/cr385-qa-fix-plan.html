QA-385-001

Bill / Checkout — room block is hard-coded, bill never reconciles with the row

P0BUG
Screen: Departures › Bill (?bill=102, ?bill=113) · Code: line 560 const adv=100, roomAmt=1000 · Phase 1 · Needs decision A (Checkout v2.9 locked)
Actual
Every guest's bill shows Booking amount ₹1,000 − Advance ₹100 (UPI) + SGST ₹25 + CGST ₹25 = ₹950 regardless of room type, nights or real advance.
  • Room 102 (R. Fernandes · Deluxe · 1 night): row says ₹2,150 balance due; bill Grand Total = F&B ₹734 + Transferred ₹741 + Room ₹950 = ₹2,425.
  • Room 113 (H. Shetty · 3 nights): still ₹1,000, then zeroed by a synthetic "Other room payments − ₹950" line.
Expected
Room block = rate(type) × nights − actual advance, GST on the pre-tax balance; the list's "balance due" equals the bill's Grand Total. A reviewer doing the arithmetic must get the same number on both surfaces.
Suggested fix
  1. Add fields to the guests seed: type-based charge via bookingCharge(g), prepaid, payMethod.
  2. Bill room block reads bookingCharge(g) and g.prepaid instead of constants; GST = 2.5 % + 2.5 % of pre-tax balance.
  3. Derive g.bal = room balance + F&B + transferred, so the row can never disagree with the bill.
  4. Keep the collapsed-ledger layout (D13/D14) — figures only.
How it is tested
testing_agent: for rooms 102, 113, 101 → room-booking-amount = rate × nights, room-advance-amount = seed prepaid, grand-total-amount equals the row ₹ cell; all previous Bill regressions (discounts, coupon, loyalty, payment pills, Print, Checkout counters).
