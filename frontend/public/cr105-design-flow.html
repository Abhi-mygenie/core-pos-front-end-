MyGenie POS · UrbanPiper Integration (Swiggy / Zomato) · 2026-07-25

1
New Aggregator Order Arrives (Socket)
Channel: aggregator_order_478 — Separate from regular orders
Socket payload: ['aggrigator-order', 40458, 478, 0, {full_order_payload}]
Same for both Swiggy & Zomato — UrbanPiper middleware abstracts both platforms. Source identified via order_details_order.order_plateform = 'swiggy' or 'zomato'

FE Handler chain:
useSocketEvents.js receives event → socketHandlers.js::handleAggregatorNewOrder() → aggregatorTransform.fromAPI() normalizes nested payload → OrderContext.addOrder() merges into orders[] → auto-filters into deliveryOrders (since orderType = 'delivery')

f_order_status = 0 (NEW for aggregator) — not in current F_ORDER_STATUS map. Will be added as 0: 'aggregatorNew'. Regular POS/Web orders never use status 0.

No "View" button — all data visible in the popup. Actions: Reject + Accept only.

2 Dashboard Views — Aggregator Rendering
TableCard (Grid View) + OrderCard (Order View) — both need S/Z badge + aggregator handling
Dashboard has exactly 2 views (toggled via view-toggle button in sidebar):
• View 1 — Table/Grid View: Uses TableCard (compact 160px grid cards) — shows table number, status pill, basic action buttons
• View 2 — Order/List View: Uses OrderCard (full detailed cards) — shows order number, amount, items, customer, rider info, all action buttons
Both views share the same channel columns (Dine-In, TakeAway, Delivery, Room).
Both components need aggregator handling.
