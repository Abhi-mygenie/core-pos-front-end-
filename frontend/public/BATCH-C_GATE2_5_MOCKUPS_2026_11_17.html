New columns for late_cancel events:
  • Risk — badge with 5 colors: OK Doubt Risk High Risk Unknown
  • Punch Time — when item was ordered (null → "—")
  • Duration — minutes between punch and cancel. High risk (30m+) in bold red. Unknown → "—"
  • High Risk rows get subtle red background highlight
  • Multi-day gaps show "+Nd" suffix (e.g., "21:23 (+2d)")

New columns for cancel_after_unpaid events:
  • Status — Unpaid (direct fraud) or Re-Paid (laundering pattern — order re-paid before cancel)
  • Made Unpaid — timestamp of first make_unpaid action
  • Gap — minutes between first unpaid and cancel
  • Unpaid Count — how many times order was made unpaid (3× = highly suspicious)
  • All rows get red background — these are always suspicious events

Key design decisions for "All" view:
  • "Detail" column — consolidated context column that adapts per event type:
    Late Cancel → risk badge + duration
    Cancel+Unpaid → paid/unpaid badge + unpaid count + gap
    Discount → operation badge + discount value
    Others → "—"
  • 7 universal columns in "All" view (compact). Filter-specific views expand to 8–10 columns with full detail.
  • Color-coded type badges distinguish 9 event types at a glance

Open Design Decisions

OD-DESIGN-01: Should the "Late Cancel" filter chip show a sub-filter for risk tiers (OK/Doubt/Risk/High Risk/Unknown), or is the table-level sorting sufficient?
OD-DESIGN-02: For the "All" view, should the "Detail" column be a single combined column (compact, as shown in M5), or should event-specific columns always be visible (wider, more explicit)?
OD-DESIGN-03: Should CR-546 "Replace" event pairs be visually grouped (e.g., connected row styling, "Old → New" labels), or shown as separate rows with the purple "Replace" badge linking them?
