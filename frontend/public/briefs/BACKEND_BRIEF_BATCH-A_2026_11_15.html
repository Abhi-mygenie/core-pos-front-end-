0. Contract rules (owner R19–R21)

  1. Names are fixed. Endpoints, field names, types and enum values are as written in each CR's contract file (linked per section). Contracts APPROVED by owner 2026-11-15 (R20).
  2. Backend may only answer ✅ OK · ⏱ ETA · ❌ not feasible (with reason).
  3. No renames. A reply or handover file that renames, retypes, drops or adds a field, or changes an enum → REJECTED, not merged, back to owner. Only the owner changes a contract.
  4. Existing keys are never renamed. If a key already exists for something marked NEW, backend gives its exact current name and FE uses it as is. New keys only when none exists, exactly as written.
  5. Additive only: existing requests/responses keep working.
  6. Errors: HTTP 403 (right/PIN) or 422 (validation) with { "error_code": "<CODE>", "message": "<text>" }.
  7. Yes/No flags as strings "Yes"/"No". Money in ₹, 2 decimals, incl. tax where a threshold is compared. Business day = restaurant schedule / day-closure.
  8. Checklist use: when a reply arrives, FE agent fills Backend reply, Match (✅/❌) and Date per row. Any ❌ → reply rejected. All ✅ → the CR's plan may be frozen.
