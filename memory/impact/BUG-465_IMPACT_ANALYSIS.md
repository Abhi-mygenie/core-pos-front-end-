## 1. What is changing and why

`recharts@3.6.0` declares `"es-toolkit": "^1.39.3"` as a dependency. Without a committed
lockfile, npm resolves this to the latest compatible version. Currently installed: `1.52.0`.

Versions `>=1.47.0` contain a CommonJS compat shim that Terser cannot safely minify.
On `npm run build`, the internal helper is mangled → `TypeError: mR is not a function`
on first chart render in the production bundle.

**Fix:** Pin `es-toolkit` to `1.46.1` via npm `overrides` in `package.json`. This forces
npm to install exactly `1.46.1` for all packages that depend on `es-toolkit`, regardless
of their stated range. `1.46.1` satisfies recharts' `^1.39.3` range and was stable in
production for 3+ months prior to `1.47.x` being released.

## 4. Data Flow / Break Point Trace

```
npm install (no lockfile, no overrides)
  → es-toolkit@1.52.0 installed
  → recharts uses es-toolkit/compat/* shim
  → npm run build (craco → webpack5 → Terser)
  → Terser mangles es-toolkit internal helper → broken binding
  → production bundle: chart component mount → TypeError: mR is not a function
  BREAK POINT: Terser minification of es-toolkit compat shim

npm install (WITH overrides: { "es-toolkit": "1.46.1" })
  → es-toolkit@1.46.1 installed (forced)
  → recharts uses es-toolkit/compat/* shim (v1.46.1 — stable under Terser)
  → npm run build → Terser minifies safely → production bundle clean
  RESULT: chart pages render correctly in production
```

## 5. Blast Radius

Only `recharts` (and its own deps) use `es-toolkit` in this project — no other packages affected.

**Build output:** All 30 files that import recharts now build cleanly:

**Runtime (dev server):** No change — dev build is unminified; the crash never manifested in dev.

## 6. Risk Classification

**Risk: HIGH (build-level change)**

- If `1.46.1` had a different bug that manifests under minification → chart pages would
  still crash. Mitigated by the fact that `1.46.1` was stable in production for 3+ months.
- If npm `overrides` syntax is wrong → `npm install` may warn or error.
  Mitigated: npm 8.3+ `overrides` is a standard field; syntax is straightforward.
- If a future dependency also requires `es-toolkit` at `>=1.47.x` → the pin would conflict.
  Mitigated: only `recharts` uses `es-toolkit` in this project (grep-verified).

**Fast Lane eligible: NO** — dependency change with LARGE blast radius; requires production
build regression.
