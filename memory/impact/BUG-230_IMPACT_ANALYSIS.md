## 1. Data Flow Trace

```
New employee row (after BUG-229):
  addRow() → email: '' (empty)
  updateNewRow('firstName', value)
    → BUG-229: auto-generates email as firstname@restaurantname.com
    → BUG-230: need to track that email was AUTO-generated

User manually edits email:
  updateNewRow('email', value)
    → BUG-230: need to mark email as MANUALLY edited

User changes firstName again:
  updateNewRow('firstName', value)
    → BUG-230: IF email was auto-generated → re-generate
    → BUG-230: IF email was manually edited → DO NOT overwrite

Existing employee:
  updateExisting(id, 'firstName', value) [L77-83]
    → Currently only updates firstName in editBuffer
    → BUG-230: need same sync logic for existing employees
    → BUT: existing employees already have emails — consider them "manually set" unless
      email currently matches auto-gen pattern
```

## 2. Changes Required

### Change 1: Track auto-generated vs manual email (new rows)
```
File: EmployeeListView.jsx
Approach: Add `_emailAutoGen: true` flag to each new row.
  - Set true when email is auto-generated by BUG-229 logic
  - Set false when user manually edits the email field
  - On firstName change: check flag → re-gen if true
```

### Change 2: Email onChange handler (new rows)
```
File: EmployeeListView.jsx — email Input onChange [L230]
When user types in email field:
  → mark _emailAutoGen = false for that row
  → proceed with normal updateNewRow
```

### Change 3: firstName onChange sync for existing employees
```
File: EmployeeListView.jsx — firstName Input for existing [L281]
On firstName change for existing employee:
  → Check if current email matches auto-gen pattern: firstname@restaurantname.com
  → If yes → re-generate email with new firstName
  → If no → leave email unchanged (user or system had set a different email)
```

### Change 4: Pattern-match heuristic for existing employees
```
Since existing employees don't have _emailAutoGen flag,
use pattern matching: currentEmail === expectedAutoGenEmail(currentFirstName)
If match → treat as auto-generated → sync on name change
If no match → treat as manually set → no sync
```
