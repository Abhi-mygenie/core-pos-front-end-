### CR-429 — Active Table Toggle
**Description:** In table view (Channel or Status), want a toggle to show ONLY occupied/active tables, or show active tables first.
**Code trace:** `DashboardPage.jsx:1110` — `showGridView = activeView === "table"`. L1956-1967 shows active table counting logic exists but no UI toggle to filter by active status. `allTablesList` is passed without active-only filter.
**Recommendation:** New feature — add a toggle button in the table view header. Filter: `tables.filter(t => !["available","reserved"].includes(t.status))` already used in some places. 
**Blast radius:** SMALL — DashboardPage.jsx + possibly TableCard rendering.

### BUG-571 — Order View Card Gaps
**Description:** In order view, table cards have gaps/empty spaces — should be tiled consecutively.
**Code trace:** `ChannelColumn.jsx:L285-288` — order view uses `repeat(${actualColumns}, 1fr)`. With groups rendered as separate `flex-col gap-2` sections, empty groups show gaps. If a group has "No active items" text, it creates visible vertical space between status groups.
**Root cause hypothesis:** The "No active items" text takes up height when a status group has no orders. In order view, all groups display together with headers, creating visual gaps between groups.
**Recommendation:** Investigate if "No active items" empty-state should be hidden in order view, or if the flex/grid should compact.

### BUG-573 — Variation Selected Option Not Shown
**Description:** Order card shows the variation GROUP NAME (e.g., "Choice of milk") but not the SELECTED OPTION (e.g., "oat milk"). Screenshot confirms "Choice Of Dip", "Choice Of" without values.
**Code trace confirmed (HIGH):** `OrderCard.jsx:L699-711`:
- L701-704: If `v.labels` array exists → returns `"GroupName: SelectedOption"` ✅ 
- L707-710: Falls back to `v.value || v.option_label || v.label || v.selected_option || ''` — if none of these fields exist on the variation object from the backend, it returns only the group name.
**Root cause:** The backend response for running orders returns `item.variation` in a structure where the selected option value is not in `v.value` / `v.option_label` etc. Need to check what field actually carries the selected option label in the running-orders API response.
**Next step:** Backend probe — inspect `item.variation` raw structure from API for an order with variations.

### BUG-574 — No Item Timing in Serving State
**Description:** Items in "serving" state show no elapsed time. Looking at screenshots, "Serve: 0m" appears for recently served items.
**Code trace:** `OrderCard.jsx:L762-769`:
- `preparing` → shows prep elapsed
- `ready` → shows Prep + Wait times
- `served` items (L847-850) → shows Prep + Serve time, but `serveAt` is the timestamp when marked served
- No `serving` status exists in the code — items go `preparing → ready → served`
**Root cause hypothesis:** `serveAt` field may not be populated by backend when item is served, so `item.serveAt` is null → Serve: 0m. The timing branch `{item.serveAt ? ...}` (L850) produces nothing when serveAt is null. This is likely a backend data gap.
**Next step:** Backend probe — check if `serve_at` field is populated in order items API response.

### BUG-575 — Order Card Header Click Doesn't Open Order Screen
**Description:** Clicking the card HEADER doesn't open the order entry screen. Expected: any click on the card (including header) should open the order.
**Code trace CONFIRMED (HIGH):** `OrderCard.jsx:L453-468`:
- Root div (L456): `onClick={() => onEdit?.()}` — card opens order on click ✅
- Header div (L468): **`onClick={(e) => e.stopPropagation()}`** ← THIS BLOCKS THE CLICK
- The header's `stopPropagation` prevents the card root's `onEdit` from firing.
**Fix:** Remove `onClick={(e) => e.stopPropagation()}` from the header div, OR move it to specific interactive elements inside the header (merge/shift/cancel buttons) to allow the card-level click to pass through.
**Fast Lane:** YES — targeted, 1 line. Header buttons should individually stopPropagation, not the entire header div.
**Risk:** LOW — but must verify header action buttons (merge, shift, cancel) still stop propagation individually.

### BUG-576 — Room Number Search Not Working
**Description:** Searching "106" (room number) in search bar shows "No orders" even though Room 106 exists and has orders.
**Code trace confirmed (HIGH):** `DashboardPage.jsx:L1257-1259`:
```js
results.rooms = searchItems(enrichedRooms, query, item => ({
  id: item.id,
  all: [opts.includes('table no') && item.id, opts.includes('user id') && (item.guestName || item.guest || '')].filter(Boolean)
}))
```
- Room search only checks `item.id` (internal DB ID, NOT the room number label) and guest name.
- Room number "106" is NOT `item.id` — it's a label like `item.name` or `item.roomNo` or `item.room_number`.
**Fix:** Add room number/name field to the search fields array for rooms (same as `table no` adds `tableNumber` for tables).
**Fast Lane:** YES — 1-line addition to room search fields.

### BUG-577 — Cancelled Items Appearing on Print Bill
**Description:** When printing a bill, cancelled order items are still appearing on the printed bill.
**Code trace:** `orderTransform.js:L1847-1851` — `isDetailCancelled` filter IS applied in `buildBillPrintPayload`. Checks `food_status===3 || cancel_at != null || cancel_type != null`. 
**Possible gap:** If a cancelled item doesn't have `cancel_at` or `cancel_type` set by backend (partial cancel scenarios), it would slip through. OR: the issue is on a different print path (aggregator print, which uses a different endpoint). OR: the order's `rawOrderDetails` doesn't include the cancellation markers.
**Recommendation:** Backend investigation — check if `rawOrderDetails` for cancelled items carries the expected `food_status`, `cancel_at`, `cancel_type` fields.
