## Findings

### F1 — TC-124-06: Remember-Me Pre-Fill Lost After Logout (MINOR)

**Root Cause:** `authService.logout()` line 63 preserves `user_email` when `REMEMBER_ME` is set, but line 67 then removes `REMEMBER_ME`. The consumer `getRememberedEmail()` gates on `REMEMBER_ME` being truthy — so the preserved `user_email` is unreachable on the login page.

**Classification:** MINOR — convenience UX regression. Core logout, token invalidation, and security flows all work correctly. Pre-fill was a pre-existing UX nicety.

**Fix options (for Bug Fix agent):**
- Option A: Remove `localStorage.removeItem(STORAGE_KEYS.REMEMBER_ME)` from `authService.logout()` — keep the flag so pre-fill works. Clear only on explicit uncheck.
- Option B: Change `getRememberedEmail()` to read `user_email` independently of the `remember_me` flag.

### N1 — Toast Description Spec Deviation (NOTE)

Toast description renders axios `readableMessage` ("Cannot reach server. Check your internet connection.") instead of CR-specified text ("Could not reach the server. Please try again."). Title "Logout Failed" and destructive variant are correct. This is a spec wording issue, not a functional bug.

### N2 — Sidebar clearInsightsCache() Timing (NOTE)

`clearInsightsCache()` runs before the awaited API call in `handleLogout`. On API failure, insights cache is already wiped while user stays logged in. Minor inconsistent state — no user impact since cache is re-fetched on next navigation.
