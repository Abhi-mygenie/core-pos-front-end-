### F4 — BLOCKER: weight popup adds the wrong weight
- **Outlet / item:** Kashi Sweets, Gopal Bhog ₹460/Kg
- **Steps:**
  1. Shortcuts ON, open a new order.
  2. Type `Gopal Bhog` and press Enter. The weight popup opens with `1000` in the box and the cursor at the end.
  3. Type `500` and press Enter.
- **Expected:** 500 gm, ₹230
- **Actual:** the box shows `1000500` and the preview says "1000.5 Kg × ₹460/Kg = ₹460230.00". Enter adds a **1000.5Kg line at ₹4,60,230**, and Collect Bill shows ₹4,60,230.
- **Evidence:** screenshots p6_11 (popup showing 1000500) and p6_12 (cart line ₹4,60,230). Script output: `value '1000', selection none → after typing '1000500'`.
- **Cause (from reading the code only):**
  - The `WeightEntryModal.jsx` weight input has `autoFocus`, the value is pre-filled, and the text isn't selected. This came **before** CR-482: `autoFocus` isn't in the P6 diff.
  - P6's Enter-to-add (`handleInputKeyDown`) now commits the bad value in one keystroke, with no button click in between.
- **File:** `frontend/src/components/order-entry/WeightEntryModal.jsx` (input around L183–197, `handleInputKeyDown` L119)
- **Note for Planning:** decide whether the fix applies when shortcuts are ON only, or for everyone. With the mouse, the same append happens if the cashier types into the box.

### F1 — MINOR: `+` / `-` typed into search
- **Steps:**
  1. Shortcuts ON, then do one of these:
     - (a) reopen a table that has only sent items (cafe103 C1),
     - (b) open a new order before adding anything, or
     - (c) right after adding a weighed item (Kashi).
  2. Press `+` or `-` in the empty search box.
- **Expected:** the plan's P8 line says "preventDefault so + is not typed".
- **Actual:** the quantity is unchanged (correct), but `+`/`-` appears in the search box and the item grid goes empty. Workaround: Backspace.
- **Evidence:** screenshots placed_2/placed_3 (search shows "+"); script output `search: '-'`, `search: '+'`.
- **File:** `OrderEntry.jsx` (P8 key handler; the skip path doesn't call `preventDefault`)

### F2 — MINOR: Ctrl+↓ start row
- **Steps:** add Americano, Banana Shake and Blue Lagoon, then press Ctrl+↓.
- **Actual:** focus goes to Americano (top row).
- **Expected:** the handover's plain wording says "starting at the newest item". The plan and PRD say "first unsent row", which is what the code does.
- **Action:** the owner picks top row or newest row; then fix either the code or the docs.
- **File:** `OrderEntry.jsx` (~L639, Ctrl+ArrowDown target)

### F3 — MINOR: cart-row highlight partly hidden
- **Steps:** add items, press Ctrl+↓, then move with ↑/↓.
- **Actual:** only an orange line above and below the focused row shows; the sides are cut off. On the first row only the bottom line shows, which can look like the second row is selected.
- **Evidence:** screenshots p10_1, p10_2, pl_a
- **File:** `CartPanel.jsx` rows (`kbd-focus` outline inside a scrolling container); CSS in `index.css`
