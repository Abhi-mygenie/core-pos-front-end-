## Root Cause Analysis (V9 + RT-1)

**Classification:** CODE_ERROR — plan was right, code deviated from existing pattern  
**Confidence:** HIGH (reproduced + traced + card-view control confirmed)

**Trace:**
```
RecipeBulkEditor.jsx L34-58 normaliseRecipe()
  → foodId: r.foodId ?? null
  → get-recipe list endpoint does NOT return food_id (known BUG-197 #7)
  → foodId stays null for ALL existing standard recipes
  → handleSave L190: payload.name = row.foodId → null
  → toAPI.updateRecipe: name: data.foodId → null
  → PUT /api/v2/vendoremployee/recipe/update-recipe/{id} → 422 "name required"
```

**Card View comparison (same endpoint, works):**
```
RecipeFormPanel.jsx L50-53 (BUG-197 #7 workaround)
  → reverse-lookups foodId from foodName against foodsMaster
  → PUT payload: {name: 168408, ...} → 200 OK
```

**Fix:** Port BUG-197 #7 workaround into RecipeBulkEditor — after `foodsMaster` loads, enrich rows: match `row.name` against `foodsMaster` to set `foodId`. RecipeBulkEditor already loads `foodsMaster` (L82-88) but never uses it to enrich existing rows.
