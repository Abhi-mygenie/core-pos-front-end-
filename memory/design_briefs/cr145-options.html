OQ-4

Addon List Fetch

The full restaurant addon pool is needed for the checkbox list. When should it be fetched?

✔ Option A — Use existing prop (recommended)

MenuManagementPanel already fetches addons when the panel opens and passes them as a prop to BulkEditor. Zero extra API calls. Addon pool is typically <50 items — no performance concern.

// BulkEditor already receives: <BulkEditor addons={addons} ... /> // Just use this.addons prop for the checkbox list

Option B — Fetch lazily per row

Fetch addon list only when user first clicks a chip. Cache for subsequent uses.

// On first expand: const addons = await menuService.getAddons(); // Cache in component state

⚠ Unnecessary — the list is already in memory. Extra network call adds latency for no benefit.

OQ-5

Array Dirty Tracking

How to detect when addon assignments have changed (to show the "unsaved" indicator and include addon_ids in save)?

✔ Option A — Sorted JSON.stringify (recommended)

Sort both arrays and compare as strings. Simple, accurate, order-independent.

const isDirty = (original, current) => JSON.stringify([...original].sort()) !== JSON.stringify([...current].sort());

✔ Works regardless of check/uncheck order · Easy to reason about

Option B — Set symmetric difference

Build Sets from both arrays and check for differences.

const isDirty = (original, current) => { const oSet = new Set(original); const cSet = new Set(current); return current.some(id => !oSet.has(id)) || original.some(id => !cSet.has(id)); }

Works fine but more verbose. No real benefit for <50 addons.
