Wastage Report Endpoint

Required to power the Wastage Insights + Top Wasted Items widgets on the Inventory Intelligence dashboard (CR-072 Phase 2).

P1 · MEDIUM
Filed: 2026-07-18
From: Frontend (Planning Gate 2)
Sprint: pos_5_0

Summary

Frontend needs an aggregated wastage report endpoint so the Inventory Intelligence dashboard can visualise how much stock is being wasted, why (by reason), which items are the biggest offenders, and who recorded each entry. Currently the FE has no read path for wastage — the add-stock endpoint writes wastage events (when a wastage_reason_id is passed) but there is no companion list/report endpoint.

Consuming widgets

Widget A
Wastage Insights

  • Delta vs previous period (“18 % above 30-day avg”)
  • Headline: total wastage ₹ for range
Widget B

Nice-to-have

Optional enhancements (P2)

  • Add previous_period_total_value to each wastage_summary row → enables ↑↓% trend arrow per item. Without it FE calls the endpoint twice with different ranges, which is acceptable but heavier.
  • Add top-level by_restaurant array (same as vendor-item-list) — for master-outlet consolidated view (children roll-up).
  • Add unit_rate_used per wastage_details row → shows FE the exact price used in the ₹ calc so we can display “Milk lost @ ₹60/ltr”.

Business rules · Owner-approved

#RuleDecision
1 How is wastage_value (₹) computed for each event? Multiply wastage_qty_raw × the latest known unit_price for that ingredient_id at the moment the report is generated. (Not the historical rate at time of wastage — accept the small drift; simpler backend, matches owner ruling 2026-07-18.)
2 Include raw wastage events (user + timestamp)? YES — future “Wastage Log” page will list every event. Ship user_id, user_name, source_type from day one so no schema change is needed later.
3 Which entries count as “wastage”? Any add-stock call with wastage_reason_id present AND resulting stock delta < 0 (i.e. the stock was reduced, not added). Positive drifts (physical count found extra) are not wastage.
4 Scope of restaurants Auth token → single restaurant by default. For master outlets (restaurant_type_flag === "master") with children, include roll-up if by_restaurant nice-to-have is implemented.
5 Empty results Return empty arrays + total_wastage_value: 0. Do not return null or 404.

Acceptance criteria (FE will test)

  1. Endpoint responds 200 with an empty-shape payload when no wastage exists in range.
  2. Every wastage_summary row has a matching group of wastage_details rows whose numeric qty sums to total_wastage_qty_raw (±0.01 rounding).
  3. SUM(wastage_by_reason.total_value) === total_wastage_value.
  4. SUM(wastage_details.wastage_value) === total_wastage_value.
  5. An add-stock call with negative drift + wastage_reason_id appears in this report’s next call.
  6. Filters (ingredient_id, category_id, reason_id) return only matching rows in both summary and details.
  7. User-recorded events show the correct user_name (matches employee.name from employee master).
