Single-Call Multi-Vendor Purchase Endpoint

Optimisation for the Smart Purchase (CR-078) submit path. Not release-blocking — CR-078 ships with N sequential calls (Q7-a). This brief unlocks atomicity + performance later.

P2 · MEDIUM
Filed: 2026-07-18
From: Frontend (Planning Gate 2 close)
Sprint: pos_5_0+

Why this exists

Smart Purchase (CR-078) ends the planner with N line items grouped by M vendors. Ship-1 approach (owner ruling Q7-a) fires M sequential POST /add-stock calls — one per vendor. That's fine when M ≤ 5 and network is stable. It becomes fragile as scale grows:

  • No atomicity — if call 3 of 5 fails, calls 1-2 already persisted, 4-5 never fired. Client has to reconcile.
  • M× auth + M× network latency = slow submit UX on large baskets.
  • Race conditions on stock ledger writes.
  • Reporting is fragmented — one "purchase decision" produces M unrelated purchase rows in the DB.

This brief proposes a single-call multi-vendor purchase endpoint that groups all lines in one transaction.

Proposed endpoint

MethodPOST
Path/api/v2/vendoremployee/purchase/bulk
AuthBearer token · same as /add-stock
AtomicitySingle DB transaction · all-or-nothing (see Rule 1)

Business rules

#RuleDecision
1AtomicityAll vendor POs in one DB transaction. If ANY line fails validation, roll back the entire request. Return 422 with the failing vendor/line identified.
2IdempotencyFE sends planner_reference. Backend must reject re-submission of the same reference within 5 minutes with 409 DUPLICATE_PLANNER_REF.
3Ad-hoc vs planner linesSame call accepts both. origin field on each line is for audit/reporting only.
4Payment method required per vendorOwner ruling B1. 422 if any vendor block missing payment_method.
5Rate > 0Owner ruling B2. 422 if any line has rate ≤ 0.
6Backwards compatibilityDo NOT deprecate /add-stock — retain it for Stock Audit adjustments (which pass wastage_reason_id). Purchase-bulk is a NEW route, not a replacement.
7Vendor deduplicationBackend rejects duplicate vendor_id entries in one request (422 DUPLICATE_VENDOR) — FE should have already grouped by vendor.

Error codes

CodeHTTPTrigger
auth-001401Missing/expired token.
VALIDATION_FAILED422Any line invalid — must include failing_vendor_id + failing_line_index.
DUPLICATE_PLANNER_REF409Same planner_reference within 5 min.
DUPLICATE_VENDOR422Same vendor_id twice.

Acceptance criteria (FE will test)

  1. 2-vendor / 4-line submit returns 200 with 2 purchases_created entries.
  2. Same planner_reference re-submitted within 5 min → 409.
  3. Rate = 0 on any line → 422 with the failing line identified · nothing persisted.
  4. Server-side crash mid-request → nothing persisted (roll back).
  5. /stock-inventory reflects deltas immediately after 200 response.
  6. Old /add-stock continues to work for Stock Audit adjustments.
