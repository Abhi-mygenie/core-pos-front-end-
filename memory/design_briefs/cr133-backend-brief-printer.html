Summary Additive
What this brief asks for and why

The printer-agent-config endpoint currently stores font-size + bold settings that the print agent applies when rendering receipts. Three new configuration capabilities are needed to let restaurant owners control what appears on their bills and KOTs, in what order, and how it's aligned — without requiring a code push.

The FE UI for all three features is built. Config keys are already being sent in the POST body and stored by the backend. The live preview in the POS settings screen already reflects these settings. Actual printed receipts will only change after the print agent reads the new keys.

⚠️
Current limitation
The print agent template layout is currently hardcoded — font sizes and bold are the only dynamic values. All three new capabilities require the print agent to read and apply the new config keys.
Contract Addition A — Field Visibility Phase 2
Show or hide specific fields on bill and KOT receipts

A.1 New key location

Add field_visibility as a top-level key inside settings_config, alongside auto_printing, printers, etc.:

{
  "settings_config": {
    "auto_printing": { ... },
    "printers": [ ... ],
    "field_visibility": {
      "bill": {
        "show_waiter_name":          true,
        "show_customer_name":        true,
        "show_customer_phone":       false,
        "show_order_note":           true,
        "show_token_number":         true,
        "show_gst_breakdown":        true,
        "show_cgst_sgst_split":      true,
        "show_service_charge_line":  true,
        "show_discount_line":        true,
        "show_coupon_line":          false,
        "show_tip_line":             true,
        "show_delivery_address":     true,
        "show_upi_qr":               false,
        "show_feedback_qr":          false,
        "show_bill_footer":          true
      },
      "kot": {
        "show_waiter_name":   true,
        "show_customer_name": false,
        "show_order_note":    true,
        "show_station":       true,
        "show_item_notes":    true,
        "show_token_number":  true,
        "show_date_time":     true
      }
    }
  }
}

A.4 Print agent behaviour rules

  • If key is absent from config → treat as true (backwards-compatible fallback)
  • If key is false → omit that element from ESC-POS output entirely — no blank line, no label
  • Keys that are true but data is empty (e.g., waiterName: '') → still omit (existing behaviour, unchanged)
  • show_delivery_address only applies when order type is delivery — ignored for dine-in/takeaway
Contract Addition B — Alignment Phase 2
Left, center, or right alignment per section in bill/KOT print style

B.1 Current vs new structure

Current (unchanged)

{
  "restaurant_name": {
    "font_size_58mm": 11,
    "font_size_80mm": 17,
    "bold": "Yes"
  }
}

New (additive — add alignment)

{
  "restaurant_name": {
    "font_size_58mm": 11,
    "font_size_80mm": 17,
    "bold": "Yes",
    "alignment": "center"
  }
}

B.2 Valid values

"left" | "center" | "right"

B.3 Default alignment per section (when key is absent)

SectionDefaultRationale
restaurant_header.*"center"Restaurant name centered is standard practice
bill_information.*"left"Info rows (order#, table, waiter) left-aligned
item_table.table_header"center"Column headers centered
item_table.table_content"left"Item names left-aligned
amount_section.*"right"Amounts right-aligned is standard
footer.*"center"Footer centered
kot_header.kot_title"center"KOT title centered
kot_information.*"left"KOT info rows left-aligned

B.4 ESC-POS alignment commands

// Set alignment before printing the section
left:   ESC a 0  →  \x1Ba\x00
center: ESC a 1  →  \x1Ba\x01
right:  ESC a 2  →  \x1Ba\x02

// IMPORTANT: Reset to left after each section to prevent carry-over
After each section: send ESC a 0  →  \x1Ba\x00
ℹ️
Scope
alignment applies to ALL rows in both bill_print_style and kot_print_style. The key is optional on every row — absent = use the section default from B.3.
Contract Addition C — Dynamic Row Content Phase 2
Configure what data field appears in each of the 4 bill/KOT info rows
⚠️
Problem
bill_information.row_1..4 and kot_information.row_1..4 currently only store font/bold. What content appears in each row is hardcoded in the print agent template. Restaurant owners cannot configure which data field goes where.

C.1 Current structure

{
  "bill_information": {
    "row_1": { "font_size_58mm": 6, "font_size_80mm": 7, "bold": "No" },
    "row_2": { "font_size_58mm": 6, "font_size_80mm": 7, "bold": "No" },
    ...
  }
}
// What row_1..4 show is HARDCODED in the print agent template

C.2 New structure

{
  "bill_information": {
    "row_1": {
      "content":       "order_number_date",
      "visible":        true,
      "font_size_58mm": 6,
      "font_size_80mm": 7,
      "bold":           "No",
      "alignment":      "left"
    },
    "row_2": {
      "content":        "table_waiter",
      "visible":        true,
      "font_size_58mm": 6,
      "font_size_80mm": 7,
      "bold":           "No",
      "alignment":      "left"
    },
    "row_3": {
      "content":        "customer_name",
      "visible":        true,
      "font_size_58mm": 6,
      "font_size_80mm": 7,
      "bold":           "No",
      "alignment":      "left"
    },
    "row_4": {
      "content":        "order_note",
      "visible":        false,
      "font_size_58mm": 6,
      "font_size_80mm": 7,
      "bold":           "No",
      "alignment":      "left"
    }
  }
}

C.5 Backwards compatibility rules

  • If content key is absent → print agent uses current hardcoded content for that row (no regression)
  • If visible: false → skip the row entirely — no blank line
  • If visible key is absent → treat as true
  • If content points to a field with empty data → skip that row (same as current empty-field behaviour)

GET Response Contract
What backend must return on GET — including defaults for new keys

When a restaurant has not yet saved these settings (or is on an older config), the GET response must include the new keys with safe defaults:

// Additions to the GET response

// In settings_config:
"field_visibility": {
  "bill": {
    "show_waiter_name": true, "show_customer_name": true,
    "show_customer_phone": false, "show_order_note": true,
    "show_token_number": true, "show_gst_breakdown": true,
    "show_cgst_sgst_split": true, "show_service_charge_line": true,
    "show_discount_line": true, "show_coupon_line": false,
    "show_tip_line": true, "show_delivery_address": true,
    "show_upi_qr": false, "show_feedback_qr": false, "show_bill_footer": true
  },
  "kot": {
    "show_waiter_name": true, "show_customer_name": false,
    "show_order_note": true, "show_station": true,
    "show_item_notes": true, "show_token_number": true, "show_date_time": true
  }
}

// Every style row gains "alignment" with section default:
"restaurant_name": { "font_size_58mm": 11, "font_size_80mm": 17, "bold": "Yes",
  "alignment": "center" }

// Every info row gains "content" + "visible":
"bill_information": {
  "row_1": { "content": "order_number_date", "visible": true, "font_size_58mm": 6, "bold": "No", "alignment": "left" },
  "row_2": { "content": "table_waiter",      "visible": true, "font_size_58mm": 6, "bold": "No", "alignment": "left" },
  "row_3": { "content": "customer_name",     "visible": true, "font_size_58mm": 6, "bold": "No", "alignment": "left" },
  "row_4": { "content": "order_note",        "visible": true, "font_size_58mm": 6, "bold": "No", "alignment": "left" }
}
