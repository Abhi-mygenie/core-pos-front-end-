## 1. Plain-English plan
- **M4 Extend Stay** — In-House / Departures row → **Extend** opens an inline form (like Modify/Check-In): new check-out date (min = current +1; shorter also allowed, D15), reason, optional discount (% / ₹ + reason), optional collect-now (Cash / Card / UPI + ref; no Split, OD-385-18 a). RIGHT = the server bill: pending balance from the row's `charge.balance_due` → "Extension priced by the server on confirm" → after **200** the per-night lines (`nights_detail[]`: date · ₹ · source chip "rate table" / "held rate" / "held (no rate for this date)") · SGST · CGST · total · paid · balance — **all from the response `charge`**, then the list is **refetched and the row re-rendered from LR** (D55; LR wins over the response). **409** (room taken on the new dates) → the blocking booking is shown and free same-type rooms are offered from `room-availability`; Confirm needs a room pick (`new_restaurant_table_id`). Rooms tab occupied tile → Extend live too.
- **M5 Balances** — the P0 placeholder ₹ (`charge.balance_due`) on In-House and Departures becomes the real **stay balance** = room ledger + room-service orders + transferred F&B incl. GST, computed **once** by `frontDeskService.getRowBalances` (calls the existing `pmsService.getInHouseGuests` and joins by `orderId`, no maths copied) — and rounded with **the same CR-170 rule the Bill uses** (BUG-433 fix, §2). "Cleared" pill + Bill disabled when paid & 0 (X-02). Chips: Leaving today (excludes overdue), Overdue N d, Arrived today, Stayover. Row actions **Request HK / Mark Clean** live (`patchRoomStatus`, same call as the Rooms tab); **Bill** stays P4-gated.

## 5. Top-five risks
1. **BQ-385-22 LR latency (1–10 s)** — after extend the D55 refetch may lag; UI must keep the 200 response figures until LR arrives (skeleton, not stale ₹). Mitigation: keep response `charge` as interim, swap on refetch; QA asserts no ₹ flash.
2. **`getInHouseGuests` cost** — it fans out folio calls per stay (BUG-421 step 3). On 20+ in-house rows the balance column may take seconds. Mitigation: one call per snapshot, `balances` state independent of the table render (placeholder "…" then value); accept for Beta, log timing; A1 snapshot (BQ-385-02) is the real fix.
3. **Held vs calendar semantics** — `extend_rate_mode` is per property (M7); the form must never label a price itself — chips only from `nights_detail[].source`. Owner smoke S-03 needs the backend wipe→restore recipe (D68) for `held_fallback`.
4. **409 move flow** — free rooms list depends on `room-availability` for the *new* window; wrong window = wrong offer. Mitigation: window = current check-in → new check-out; unit test.
5. **Rounding rule surprise** — rows will show 2,213 where the old In-House page shows 2,212.35. Mitigation: tooltip with raw + round-off; note in smoke pre-read; BUG-433 closure text.
