## E1 — Edit `frontend/package.json`

**Current state (verified at HEAD):**
`package.json` has no `overrides` or `resolutions` field. Ends with `"packageManager"` field.

**Exact change:**

Find the line:
```json
  "packageManager": "yarn@1.22.22+sha512.a6b2f7906b721bba3d67d4aff083df04dad64c399707841b7acf00f6b133b7ac24255f2652fa22ae3534329dc6180534e98d17432037ff6fd140556e2bb3137e"
```

Add BEFORE the closing `}` of the root object:

```json
  "overrides": {
    "es-toolkit": "1.46.1"
  }
```

**Full context of the change (last 4 lines of package.json after edit):**
```json
  "packageManager": "yarn@1.22.22+sha512...",
  "overrides": {
    "es-toolkit": "1.46.1"
  }
}
```

**Rationale:**
- npm `overrides` (npm 8.3+) forces all transitive dependents of `es-toolkit`
  to use exactly `1.46.1`.
- `1.46.1` satisfies recharts' declared range `"^1.39.3"`.
- `1.46.1` was the last stable version before the Terser-incompatible compat
  shim was introduced in `1.47.x`.

## Step 2 — Clean Install

```bash
cd /app/frontend
rm -rf node_modules package-lock.json
npm install
```

**Why clean wipe:**
- Any existing `node_modules` may contain `1.52.0` (currently installed).
- npm `overrides` only takes effect on a fresh resolution.
- Wipe ensures the lockfile is regenerated with `1.46.1` pinned.

**Expected output:**
- `npm install` exits 0
- Possible warnings about peer deps or deprecated packages — these are pre-existing and not caused by this fix
- `package-lock.json` is created
