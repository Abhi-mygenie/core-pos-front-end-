## What the owner wants
1. Place Order + Collect Bill payloads must send **item-level discount** (today every item sends hardcoded `discount_amount: '0.00'`).
2. Items flagged **`give_discount = 'No'`** must be **excluded** from discount entirely.

## Investigation results you can trust (code-verified 2026-06-11, commit lineage `1f05d05`+)
- Discount is **order-level**: one formula on aggregate `itemTotal` of `billableItems`.
  - Place Order / QSR: `CartPanel.jsx:384-387` (presetDiscount, manualDiscount on itemTotal).
  - Collect Bill: `CollectPaymentPanel.jsx:514-527` (+ coupon/loyalty/wallet), `discountRatio` GST proration at `:579-583`.
- Per-item payload: `orderTransform.js:603` → `discount_amount: '0.00'` hardcoded in `buildFoodItem()`.
- `give_discount` flag lives ONLY in menu management (`menuManagementTransform.js:95/245`, `ProductForm.jsx:363` "Allow Discount", `BulkEditor.jsx:27`). **`productTransform.js` does NOT map it** → cart items never have it → billing engine can't see it.
- Exclusions that DO work today (copy this pattern — BUG-018 complimentary carve-out): cancelled, complimentary (catalog+runtime), check-in markers, room-balance pass-through (L2, `CollectPaymentPanel.jsx:167/1001`).

## Landmines
- **Three payload builders** must stay in lockstep — prior bugs (CR-025, BUG-114) came from fixing one path and missing others.
- `Math.round((x*pct))/100` 2-dp convention (BUG-020) — keep it; don't reintroduce integer rounding.
- Complimentary items already excluded from `itemTotal`; don't double-exclude (give_discount filter applies ON TOP of billableItems).
- QSR CartPanel and CollectPaymentPanel have duplicated math — change BOTH or totals drift between screens.
- `effectiveTotal` drives CR-021 B2 split-clearing effect (`CollectPaymentPanel.jsx:668`) — changing discount math will retrigger it; that's correct behaviour, don't "fix" it.
- Insights side (`INSIGHTS_REPORTS_AUDIT.md` A5/A8): item-vs-order discount distribution feeds report drift — once per-item discount ships, `insightsService` distribution logic should eventually read real `discount_amount` (follow-up, not in CR-028 scope).
