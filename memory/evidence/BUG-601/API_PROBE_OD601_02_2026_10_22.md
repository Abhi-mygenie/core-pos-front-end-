| 1 | `food_info` JSON wrapper | `--form 'food_info={"variations":[...]}'` | 200 "food updated successfully" | **YES** — 1 variation group saved, read back confirmed |

| 3 | Bare JSON string | `--form 'variations=[{"name":"Test",...}]'` | **422** `"The variations must be an array."` | **NO** — validation rejects JSON string |

## Conclusions

1. **Original Option A (JSON.stringify variations as standalone field) → WILL NOT WORK.** Backend validation rejects a JSON string for `variations` — requires an actual array.

2. **`food_info` wrapper → WORKS.** Wrapping variations inside `food_info={"variations":[...]}` as a JSON string field passes validation and persists correctly. This is the documented working approach.

3. **Bracket notation → WORKS.** Expanding arrays into `variations[0][name]=X` etc. also passes validation. However, this is complex to implement in JS (recursively flatten nested objects into bracket keys).

4. **Recommended FE fix: `food_info` wrapper for variations + addon_ids.**
   - Keep flat FormData fields for simple values (name, price, category_id, etc.)
   - Wrap `variations` and `addon_ids` inside a `food_info` JSON string field
   - This matches the curl example in the owner's documentation
