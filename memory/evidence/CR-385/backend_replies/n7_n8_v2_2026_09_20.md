## 2. Product contract

| Key | Type | Default | Behavior |
|-----|------|---------|----------|
| `allow_early_checkin` | bool | `false` | When **false**, refuse check-in if stay `checkin` **>** property business date (IST). Same-day and late arrival OK. |
| `pms.allow_early_checkin` | alias | same | Same column; either key works on GET/write. |
| `extend_rate_mode` | `calendar` \| `held` | `calendar` | See table below. |
| `pms.extend_rate_mode` | alias | same | Same column. |

### N8 money modes

| Mode | Extend pricing |
|------|----------------|
| **`calendar` (default)** | Held rate × **old** nights + CM sum for **added** nights only. Upgrade once. CM miss → held fallback for added nights. |
| **`held`** | Exact D4 lock: freeze `rate_per_night` before checkout mutate. |
| Shorten stay | Always held math (no CM reprice of remaining nights). |

### N8 GST (calendar)

| Field | Rule |
|-------|------|
| Rent / `booking_charge` | Sum of **sold night rates** + upgrade (same as before). |
| `rate_per_night` | **Average** `(sum night rates) / nights` — display/compat only; **not** the GST slab basis. |
| GST slab | **Per sold night** on that night’s rate (`<7500` → 5%, else 18%). Upgrade uses slab of **`max(night rates)`**. |
| `nights_detail` | Present on **calendar** extend `data.charge` only: `[{date, rate, source: held\|calendar\|held_fallback, gst_percent, gst}]`. Absent on held / Direct / modify / check-in. |

**Cross-slab (live sandbox):** nights **8600** (18%) + **7400** (5%) + upgrade **1500** (18%) → GST **2188** — see §3.1. (Synthetic 8600+6000 would follow the same per-night rule.)

**Settings write gotcha:** `POST /api/v2/vendoremployee/restaurant-settings/update-settings` requires multipart form field **`data`** = JSON string. A raw JSON body with top-level `basic` is **ignored** (returns success but values unchanged).

**Extend response shape:** charge is under **`data.charge`** (not top-level `charge`).
