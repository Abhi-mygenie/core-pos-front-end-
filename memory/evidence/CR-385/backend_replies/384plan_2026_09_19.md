## Wave 1 — `charge{}` (BQ-08 / BQ-03)

Every LR row carries server `charge`. PATCH ignores FE `amount_after_tax`; use `preview=true` for dry-run.

### 1a. List — assert `charge` + `meta` + `counts`

```bash
curl -sS "{HOST}/api/v2/vendoremployee/aiosell/local-reservations?start_date=2026-09-01&end_date=2026-10-31&view=all" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Accept: application/json"
```

Spot-check:

- `data.meta.business_date`, `data.meta.timezone` (`Asia/Kolkata`)
- `data.counts.arrivals_today` … `arrived_today`
- `data.reservations[].charge` keys: `rate_per_night`, `nights`, `booking_charge`, `sgst`, `cgst`, `total_with_gst`, `prepaid_amount`, `advance_payment`, `balance_due`

### 1b. Modify preview (no write)

```bash
curl -sS -X PATCH "{HOST}/api/v2/vendoremployee/aiosell/local-reservations/{RESERVATION_ID}" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "checkin": "2026-09-20",
    "checkout": "2026-09-23",
    "preview": true,
    "reason": "preview nights"
  }'
```

Expect: `data.preview: true`, recomputed `data.reservation.charge`, DB amounts unchanged.

### 1c. Modify persist (recompute)

```bash
curl -sS -X PATCH "{HOST}/api/v2/vendoremployee/aiosell/local-reservations/{RESERVATION_ID}" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "checkin": "2026-09-20",
    "checkout": "2026-09-23",
    "amount_after_tax": 0,
    "reason": "extend dates — FE amount ignored"
  }'
```

Expect: `amount_after_tax: 0` ignored; `data.reservation.charge` / `amount_*` recomputed from rate × nights.

Optional rateplan on a room line:

```bash
curl -sS -X PATCH "{HOST}/api/v2/vendoremployee/aiosell/local-reservations/{RESERVATION_ID}" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Content-Type: application/json" \
```

## Wave 2 — upgrade + Direct advance (BQ-09 / BQ-10)

### 2a. Check-in with paid upgrade

V1 group check-in (multipart or JSON as FE uses today). Upgrade fields:

```bash
curl -sS -X POST "{HOST}/api/v1/vendoremployee/pos/user-group-check-in" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Accept: application/json" \
  -F "phone=9876543210" \
  -F "name=Upgrade Guest" \
  -F "booking_type=Direct" \
  -F "booking_id={BOOKING_ID}" \
  -F "aiosell_reservation_id={RESERVATION_ID}" \
  -F "id_type=Aadhaar" \
  -F "room_id[]={TABLE_ID}" \
  -F "checkin_date=2026-09-20" \
  -F "checkout_date=2026-09-22" \
  -F "order_amount=6000" \
  -F "advance_payment=0" \
  -F "balance_payment=6000" \
  -F "gst_tax=300" \
  -F "total_adult=1" \
  -F "total_children=0" \
  -F "payment_method=Cash" \
  -F "upgrade_type=paid" \
  -F "upgrade_amount=1500" \
  -F "upgrade_reason=Suite request"
```

Expect: `charge` in response; folio has separate “Room upgrade” line when paid.  
`upgrade_type=complimentary` needs `upgrade_reason`, amount forced to 0.  
Paid with `upgrade_amount <= 0` → 422. Lower type assign → 422 when rates allow detection.

## Wave 5 — extend-stay (BQ-14)

Server recomputes `charge` when reservation linked; FE should stop sending `new_room_price`.

```bash
curl -sS -X POST "{HOST}/api/v2/vendoremployee/pos/room-extend-stay" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "order_id": 1232408,
    "new_checkout_date": "2026-09-24",
    "reason": "Guest requested one more night",
    "discount": {
      "type": "flat",
      "value": 500,
      "reason": "Loyal guest"
    },
    "payment": {
      "amount": 2000,
      "method": "cash"
    }
  }'
```

Room move when current room conflicts:

```bash
curl -sS -X POST "{HOST}/api/v2/vendoremployee/pos/room-extend-stay" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "order_id": 1232408,
    "new_checkout_date": "2026-09-28",
    "new_restaurant_table_id": 8525,
    "reason": "Move for extended nights"
  }'
```

Expect: `data.charge`, optional `payment_record_id`, `inventory_push` / `inventory_push_warning`. Conflict without move → **409** (message may include `booking_id=`).

## Wave 6 — auto-print, Credit/TAB, sockets (BQ-11 / 15 / 01)

### 6a. Read via profile (no separate settings-list)

FE already loads this at login — do **not** call `settings-list` just for this flag.

```bash
curl -sS "{HOST}/api/v1/vendoremployee/profile" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Accept: application/json"
```

Spot-check: `restaurants[].settings.auto_print_checkin_receipt` (bool, default `false`). Requires migration `2026_09_20_100400_…` on the env.

### 6b. Settings update

```bash
curl -sS -X POST "{HOST}/api/v2/vendoremployee/update-settings" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "basic": {
      "auto_print_checkin_receipt": true
    }
  }'
```

Then re-fetch profile (§6a) to confirm.

### 6c. Room checkout Credit = TAB (verify only)

```bash
curl -sS -X POST "{HOST}/api/v2/vendoremployee/order/order-bill-payment" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "order_id": 1232408,
    "payment_mode": "TAB",
    "payment_amount": 4500,

```

Use `TAB` (not `credit`). Receivable attaches to booking customer by phone/email.
