BUG-201 · Phase 2
Item Delete — Backend Must Return 409 When Transactions Exist
P1Enforcement
FE Phase 1 shipped: impact modal calls GET /expense/item/{id}/impact before showing confirm dialog. User sees real transaction count + amount. This is a UX warning only — Phase 2 is the hard backend safety net.

If a user bypasses the FE modal (direct API call, Postman, other client), the backend currently silently deletes the item AND all linked expense transactions — permanently destroying financial data.

Current

DELETE always returns 200. Linked transactions silently deleted. No safety check.

Expected

Item has linked transactions → return 409 with count + amount. No transactions → 200 (no change).

Endpoint
Method + URLDELETE /api/v2/vendoremployee/expense/expenses/{item_id}
Request body{ "delete_reason": "string" } (optional — FE sends "Deleted by owner")
Expected curl
Item WITH transactions → must return 409DELETE
curl -X DELETE \
  https://preprod.mygenie.online/api/v2/vendoremployee/expense/expenses/123 \
  -H "Authorization: Bearer {token}" \
  -H "X-localization: en" \
  -d '{"delete_reason":"Deleted by owner"}'

# Expected 409:
{ "message": "Cannot delete. This item has 5 linked transactions.",
  "transaction_count": 5, "total_amount": 1200.00 }

# Expected 200 when 0 transactions (no change to current):
{ "message": "Item deleted successfully." }
FE work after delivery: Read err.response.data.transaction_count in catch block → show specific toast. ~2 lines, 30 min.
