G2 Critical
Expense Entry Uses Item NAME, Not ID — Ambiguous Linkage

POST /store-expense-details body contains "expense": "Coco Powder" (string name), not "exp_master_id": 3100 (foreign key).

If two stock items share the same name (e.g., "Sugar" in Dairy and "Sugar" in Bakery), the backend cannot disambiguate which item the expense was logged against.

Current PayloadRecommended Payload
"expense": "Coco Powder""exp_master_id": 3100, "expense": "Coco Powder"
Action: Accept exp_master_id (integer FK to stock item) alongside expense (name string). If exp_master_id is present, use it for linkage. Keep expense as display fallback for backward compatibility.
G3 Critical
No Independent Category CRUD — Empty Category Creation Rejected with HTML Redirect

Categories can only be created via POST /store_expense which requires stock_title[] (at least one item). There is no way to:

• Create an empty category (e.g., pre-setup "Dairy" before adding items)
• Rename a category without re-sending all its items
• Delete a category (what happens to orphaned items?)

Additional confirmed issue (2026-07-08): When POST /store_expense is called with stock_title: [] (empty array), the backend returns an HTML redirect page instead of a proper JSON validation error. Axios follows the redirect and receives HTTP 200 from the homepage — the FE has no way to detect this failure and silently shows a "Category added" success toast while nothing was created in the DB.

Current (broken)Expected
Empty stock_title:[] → HTML redirect (misread as 200)JSON {"errors":["stock_title required"]} with HTTP 422
Action (priority fix): Return proper JSON validation errors for all invalid payloads — never redirect to homepage.

Action (category CRUD): Add 3 endpoints:
  POST /expense/category — create empty category {"category_name": "Dairy"}
  PUT /expense/category/{id} — rename category
  DELETE /expense/category/{id} — delete category (move items to "Uncategorized" or reject if non-empty)
RE-VERIFIED 2026-07-09: 4 curl probes confirm all category-level routes still absent — DELETE /categories/{id}, DELETE /category/{id}, DELETE /delete-category/{id} all return HTTP 404 NotFoundHttpException. POST /store_expense with a NEW category name returns {"errors":[{"code":"not_found","message":"Category not found for this restaurant."}]} — endpoint only ADDS items to EXISTING categories, cannot create new ones.

Live user-facing bugs blocked by this gap: BUG-158 (Add Item — worked around via POST store_expense for existing cats), BUG-159 (Add Category — parked), BUG-160 (Rename — no workaround), Delete Category misleading toast (see /app/memory/BUG-DELETE-CAT_INVESTIGATION_REPORT.md).
G15 Critical
PUT /expense/expenses/{id} Silently Ignores stock_title — Entire Item Management API Broken

The PUT /expense/expenses/{category_id} endpoint is supposed to update a category's item list. In practice it silently ignores the stock_title array entirely and only validates that category_name matches the existing name for that ID.

Confirmed via 8 curl probes (2026-07-08):

RequestResponseActual DB change
PUT /expenses/250 with 3 items incl. new TEST_ITEM{"message":"Update successful."}No change — TEST_ITEM not added
PUT /expenses/250 with only 1 of 2 existing items (remove one){"message":"Update successful."}No change — both items still present
PUT /expenses/250 with different category_name{"errors":[{"code":"not_found","message":"Category not found."}]}No change

FE impact — 4 broken user actions confirmed:
• Add Item to category → silently fails (toast says "Item added" but nothing appears)
• Rename Category → always returns "Category not found" (name mismatch on lookup)
• Bulk Save new items → silently fails for every row
• Drag & Drop cross-category → was broken (fixed in FE via DELETE+POST workaround)

FE workaround currently in place for DnD only: DELETE item → POST store_expense with new category. Not yet applied to addItem/bulkSave/renameCategory.

Action (required — blocks core UX): Fix PUT /expense/expenses/{category_id} to actually process and persist the stock_title array. Specifically:

  1. If an item title in stock_title does not exist in this category → create it
  2. If an item ID or title previously in this category is absent from stock_title → delete it
  3. Update category_name if it differs from current name (fix rename)

Alternative: Add a dedicated POST /expense/category/{id}/item endpoint to add a single item, and PUT /expense/category/{id} to rename — and formally deprecate the broken PUT endpoint.

🟡 Important Gaps — Should Have for Production Quality
G4 Important
No User/Employee Tracking on Expense Entries

API responses for expense transactions do not include created_by, employee_name, or employee_id. No way to know WHO logged an expense.

Business impact: ₹9,320 gas bill logged — by whom? Owner cannot audit staff expense entries.

Action: Add employee_id and employee_name fields to:
  • store-expense-details response
  • expenses-report response rows
  • expenses-export-report response rows
Backend should auto-populate from the authenticated user's token.
G5 Important
No Notes/Description Field on Transactions

Expense entries have no free-text notes field. Users cannot capture context like "emergency purchase from vendor X" or "price increase — was ₹80/kg last month".

Action: Add optional notes (string, max 500 chars) to:
  • store-expense-details request body (per line item in details[])
  • edit-expense/{id} request body
  • expenses-report + expenses-export-report response rows
G6 Important
No Pagination on Expense Report

expenses-report returned 765 items (6 months) in a single response without pagination. A restaurant running for 3+ years could have 10,000+ transactions.

Current data: kunafamahal — 765 txns / 6 months ≈ ~1,500/year

Action: Add limit and offset (or page) query parameters to expenses-report. Default limit: 100. Return total_count in response for FE pagination controls.
G7 Important
No Server-Side Search on Stock Master

expenses-list returns all 308 items flat. No search or category_id filter parameter. FE does client-side filtering.

Action: Add optional query params: ?search=dal&category_id=347 to expenses-list.
G8 Important
No Category Filter on Expense Report

expenses-report accepts from, to, payment_method — but no category_id or category_name filter. Cannot query "show only Dairy expenses this month" server-side.

Action: Add optional category_id query param to expenses-report.

⚠️ API Inconsistencies (FE is handling — backend cleanup recommended)
1. Field name mismatch between Create vs Update:

POST store-expense-details: expense, amount, e_date
PUT edit-expense/{id}: exp_name, d_amount, e_dates

Recommendation: Standardize to one naming convention (prefer expense_name, amount, expense_date)
2. stock_title format inconsistency:

POST store_expense: "stock_title": ["Dal", "Rajma"] (flat string array)
PUT expenses/{id}: "stock_title": [{"title": "Dal"}] (object array)

Recommendation: Accept both formats on both endpoints, or standardize to one
3. Date format inconsistency:

Most endpoints: DD/MM/YYYY (e.g., 19/06/2026)
Export report body: YYYY-MM-DD (e.g., 2026-06-19)

Recommendation: Standardize to ISO YYYY-MM-DD across all endpoints
4. URL naming inconsistency:

/store_expense (underscore) vs /store-expense-details (hyphen)

Recommendation: Use hyphens consistently (Laravel convention)
5. Amounts returned as strings:

"Amount": "60", "d_amount": "60", "quantity": "0.00"

Recommendation: Return as numbers — "amount": 60.0
