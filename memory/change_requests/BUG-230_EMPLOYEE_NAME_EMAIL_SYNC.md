## Description

When an employee's **first name** is changed, the auto-generated email should update to match — but ONLY if the email was auto-generated (not manually edited by the user).

### Rules

1. If employee name changes AND email was auto-generated (pattern: `firstname@restaurantname.com`) → **re-generate email** to `newfirstname@restaurantname.com`
2. If user manually edited the email (different from auto-generated pattern) → name change should **NOT overwrite** the email
3. Requires a tracking flag or pattern-match to distinguish auto-generated vs manually-edited email

### Current Code State

- `EmployeeListView.jsx:55` — `email: ''` (empty default, no auto-gen tracking)
- `EmployeeListView.jsx:230` — plain `<Input>` for email, no onChange sync from firstName
- `EmployeeListView.jsx:293` — existing employee email input, same — no sync
- No `isEmailAutoGenerated` flag or equivalent exists anywhere
- Depends on BUG-229 being implemented first (auto-generation must exist before sync can work)

### Implementation Dependency

**MUST implement BUG-229 first** — auto-email generation creates the baseline. BUG-230 adds the sync-on-rename behavior on top.
